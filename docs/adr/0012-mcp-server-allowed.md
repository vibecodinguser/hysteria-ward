# MCP-сервер для ИИ-агентов разрешён

**Статус:** принято (отменяет запрет ТЗ 2.4); объём только для чтения реализован

Панель **вправе** отдавать свои функции ИИ-агентам по протоколу MCP. Реализация — этап 4, не MVP. Доступ только
по ключу, даже если веб-авторизация к этому моменту ослаблена; ключ выпускается отдельно и может быть выпущен
только для чтения.

Причины: (1) требование владельца; (2) запрет ТЗ 2.4 возник как реакция на «экспортные карты для ИИ» из первых
версий ТЗ и смешивал две разные вещи — выдачу управляющего доступа агенту и подготовку данных специально под
обучение моделей; второе по-прежнему не делаем, первое — обычный API с аутентификацией; (3) у эталонного
`awg-manager` такой сервер есть и оказался востребован.

**Последствия.** Из раздела «что не делаем» уходит строка про `/mcp`-эндпоинты и API-ключи для ИИ-инструментов.
Появляется обязанность проектировать внутренний API так, чтобы его можно было отдать наружу без переписывания:
операции именованные, идемпотентные там, где это возможно, а разрушительные (удаление пользователя, применение
конфига) помечены явно. Если ключ когда-нибудь получит доступ к паролям клиентов, он станет самым чувствительным
секретом панели, и хранить его нужно будет так же, как пароль администратора; в первом read-only объёме такого
доступа нет.

**Рассмотренные варианты.** Оставить запрет — отклонено владельцем. Отдать агенту тот же HTTP-интерфейс, что и
браузеру, без отдельного ключа — отклонено: тогда агент получает доступ ко всему, включая сессии, а отозвать его
нельзя, не отобрав доступ у человека.

## Реализация только для чтения

Первый объём намеренно уже исходного решения: ключ MCP **не отдаёт пароли клиентов и ссылки `hysteria2://`**,
поэтому не является копией административного доступа. Инструменты:

- `server_status` — версия, состояние ядра, домен, режим masquerade, пределы скорости и краткое состояние
  сертификата; путь к сайту и адрес зеркала наружу не уходят;
- `users_list` — пользователи с квотой, расходом и состоянием, без паролей;
- `traffic_snapshot` — текущие байты и скорости по пользователям и суммарно.

Транспорт — `POST /mcp` по JSON-RPC 2.0 (streamable HTTP без SSE). Аутентификация — только
`Authorization: Bearer`; cookie-сессия панели и CSRF здесь не принимаются, а ключ не открывает `/api/`. Ключ
выпускается в настройках панели, показывается один раз и отзывается. В базе лежит SHA-256-хеш токена: сам токен
состоит из 256 случайных бит, поэтому медленный парольный хеш здесь не нужен — перебирать нечего. Имя ключа
уникально без учёта регистра.

Изменяющие инструменты и доступ к клиентским секретам в этот объём не входят. Для них понадобится отдельное
решение: область прав ключа, аудит и явное подтверждение опасных операций.
