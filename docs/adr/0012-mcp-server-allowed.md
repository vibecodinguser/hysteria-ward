# MCP-сервер для ИИ-агентов разрешён

**Статус:** принято (отменяет запрет ТЗ 2.4)

Панель **вправе** отдавать свои функции ИИ-агентам по протоколу MCP. Реализация — этап 4, не MVP. Доступ только
по ключу, даже если веб-авторизация к этому моменту ослаблена; ключ выпускается отдельно и может быть выпущен
только для чтения.

Причины: (1) требование владельца; (2) запрет ТЗ 2.4 возник как реакция на «экспортные карты для ИИ» из первых
версий ТЗ и смешивал две разные вещи — выдачу управляющего доступа агенту и подготовку данных специально под
обучение моделей; второе по-прежнему не делаем, первое — обычный API с аутентификацией; (3) у эталонного
`awg-manager` такой сервер есть и оказался востребован.

**Последствия.** Из раздела «что не делаем» уходит строка про `/mcp`-эндпоинты и API-ключи для ИИ-инструментов.
Появляется обязанность проектировать внутренний API так, чтобы его можно было отдать наружу без переписывания:
операции именованные, идемпотентные там, где это возможно, а разрушительные (удаление пользователя, применение
конфига) помечены явно. Ключ даёт доступ к паролям клиентов, поэтому это самый чувствительный секрет панели, и
хранить его нужно так же, как пароль администратора.

**Рассмотренные варианты.** Оставить запрет — отклонено владельцем. Отдать агенту тот же HTTP-интерфейс, что и
браузеру, без отдельного ключа — отклонено: тогда агент получает доступ ко всему, включая сессии, а отозвать его
нельзя, не отобрав доступ у человека.
