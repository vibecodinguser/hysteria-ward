# Порт-хоппинг только на клиентской стороне

**Статус:** принято

ТЗ 3.1 требует поле `portHopping` в интерфейсе экземпляра. Фактически «прыгает» всегда клиент; серверу для
приёма диапазона нужно слушать `:<range>` и **самому ставить правила DNAT/REDIRECT** (nftables или iptables,
права root), убирая их при выходе.

Решение: поддерживаем только клиентскую часть — UI генерирует URI с диапазоном портов и интервалом хоппинга, а
сервер слушает один порт. Установка правил файрвола остаётся задокументированной задачей администратора.

Причина: правка системного файрвола — ровно та системная область, которую ТЗ 2.4 запрещает менеджеру трогать
(наряду с TUN/TProxy и таблицами маршрутизации).

**Последствия.** Без ручных правил хоппинг не работает — это нужно явно объяснять в интерфейсе, иначе фича
выглядит сломанной.

**Рассмотренные варианты.** Полный server-side диапазон со своими правилами файрвола — отклонён; может вернуться
как отдельная опция под явным флагом «разрешаю менять файрвол».
