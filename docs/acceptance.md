# Приёмка v0.1

Финальная проверка: панель ставится на чистый сервер, открывается по HTTPS, пускает клиента, считает трафик и
обновляется без потери данных. Ниже — что и как проверять, и что уже проверено.

## Что нужно

- Чистый сервер Ubuntu LTS (20.04, 22.04, 24.04 или 26.04) или Debian 12/13, `amd64`/`arm64`.
- Домен, который указывает на этот сервер, и открытые порты **80** (HTTP-01) и **8443** (панель). Для клиента —
  **UDP 443**.
- E-mail для ACME.
- Клиент Hysteria 2 для проверки подключения — например,
  [официальный](https://github.com/HyNetworks/hysteria/releases) `hysteria-linux-amd64`.

Если порт 80 закрыт, вместо HTTP-01 используется DNS-01: `--acme-mode dns --acme-dns-hook <программа>`.

## Порядок

### 1. Установка

```sh
curl -fsSL https://github.com/vibecodinguser/hysteria-ward/releases/latest/download/install.sh -o install.sh
sudo sh install.sh
```

Установщик спрашивает домен, e-mail, доступ к панели, masquerade и пароль. Ответы показываются на подтверждение и
проверяются до изменений. Пароль вводится скрыто или генерируется и печатается один раз.

Проверить, что служба жива:

```sh
systemctl status hysteria-ward
journalctl -u hysteria-ward --no-pager --lines=40
```

Сертификат выпускается в фоне; в журнале появляются строки «выпуск сертификата: слежу за сроком» и «сертификат
выпущен». Пока его нет, панель работает с самоподписанным — это не ошибка установки.

### 2. Панель и сертификат

В публичном режиме:

```sh
curl -fsS https://panel.<домен>:8443/api/health
# {"status":"ok"}

openssl x509 -in /etc/hysteria-ward/certs/fullchain.pem -noout -ext subjectAltName -enddate
```

Ожидается сертификат на `<домен>` и `panel.<домен>`, выписанный ACME, без предупреждений браузера. В браузере
открыть `https://panel.<домен>:8443`, войти администратором.

В режиме SSH-туннеля:

```sh
ssh -L 8443:127.0.0.1:8443 root@<сервер>
# затем https://127.0.0.1:8443
```

### 3. Пользователь и клиент

В интерфейсе: «Пользователи» → завести пользователя → «Ключ» → скопировать ссылку или скачать QR.

Клиент:

```sh
hysteria client -c client.yaml
```

```yaml
server: <домен>:443
auth: <пароль из ключа>
tls:
  sni: <домен>
  pinSHA256: <отпечаток из ключа>
socks5:
  listen: 127.0.0.1:1080
```

Проверить трафик:

```sh
curl --socks5-hostname 127.0.0.1:1080 https://example.org/
```

В панели пользователь становится «в сети», растут «Принято» и «Отдано», обновляется график. История переживает
перезапуск панели.

### 4. Masquerade

В настройках выбрать «Свой сайт» и каталог, нажать «Применить». Посторонний запрос по HTTP/3 к серверу получает
страницу сайта; при «Выключено» — 404.

### 5. Обновление

```sh
curl -fsSL https://github.com/vibecodinguser/hysteria-ward/releases/latest/download/update.sh -o update.sh
sudo sh update.sh --dry-run
sudo sh update.sh
sudo sh update.sh --status
```

После обновления проверить: вход администратора, список пользователей, домен и отпечаток сертификата не
изменились; в `/var/lib/hysteria-ward/backups/` лежит копия базы. Повторный запуск ничего не делает.

### 6. Отказ и откат

Остановить службу, положить в `/usr/local/bin/hysteria-ward` заведомо нерабочий бинарь и запустить `update.sh` с
той же версией и `--force`. Скрипт должен вернуть прежний бинарь и копию базы и поднять службу.

## Что проверено в лаборатории

Лабораторный прогон: два одноразовых LXC на Proxmox (Ubuntu 24.04 и Debian 13), установка из локального релиза,
ACME-сервер Pebble вместо Let's Encrypt (тот же протокол ACME, HTTP-01), официальный клиент Hysteria 2.13.0.
Pebble выпускает сертификаты на `<домен>` и `panel.<домен>`, его корневой сертификат добавлен в доверенные
системы контейнера — так проверяется вся цепочка, кроме публичного доверия.

| № | Критерий | Результат |
|---|---|---|
| 1 | `install.sh` на чистом Ubuntu LTS и Debian 12/13 без ручных шагов; повторный запуск безопасен | выполнен: обе ОС, повторный запуск снял временный drop-in и не тронул базу |
| 2 | Панель по HTTPS на `panel.<домен>` с валидным сертификатом без предупреждений | частично: сертификат на оба имени, цепочка проверяется `curl` с корнем Pebble; публичное доверие требует Let's Encrypt на публичном сервере |
| 3 | Авторизация обязательна | выполнен: `/api/status` без входа — 401, после входа — 200, после выхода — снова 401 |
| 4 | По умолчанию `127.0.0.1`; публичный доступ включается и выключается без перезапуска | выполнен: переключение tunnel↔public, PID панели не изменился |
| 5 | Создание и удаление пользователя; ключ `hysteria2://` и QR | выполнен: пользователь, ключ, PNG 552×552, удаление 204 |
| 6 | Реальный клиент подключается по ключу и гоняет трафик | выполнен: официальный клиент, SOCKS5, страница получена через туннель |
| 7 | Статистика ≤2 с, графики 1ч/3ч/24ч/7д, история переживает перезапуск | выполнен: `rx/tx` и «в сети», 721 точка за час, после перезапуска точка на месте |
| 8 | Masquerade: включён — подставной ответ, выключен — нет | выполнен: HTTP/3-запрос получил страницу сайта; после off — 404 |
| 9 | `update.sh` не теряет пользователей, пароль, домен и сертификаты; повторный запуск безопасен | выполнен: v0.0.1 → v0.0.2, пользователь и отпечаток сертификата на месте, копия базы создана |
| 10 | loopback-e2e зелёный в CI | выполнен: шаг `make e2e` в CI |
| 11 | Миграция схемы bbolt работает и делает бэкап перед миграцией | покрыт тестами `internal/store`; в живом прогоне схема уже текущая, мигрировать было нечего |

Пункт 2 остаётся открытым для настоящего публичного сервера: в лаборатории нет домена, указывающего на
публичный адрес, и порт 80 наружу не проброшен. Всё остальное проверено на живых системах.

## Ограничения лаборатории

- LXC, а не отдельный VPS: ядро и systemd те же, но сеть и железо другие.
- Pebble, а не Let's Encrypt: протокол тот же, публичного доверия нет.
- Клиент и сервер в одной локальной сети: проверен туннель и учёт трафика, но не качество канала через интернет.
