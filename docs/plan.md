# План реализации hysteria2-manager

Итог проектировочной сессии по `docs/tech_spec.md`. Техническое задание считается **черновиком**: объём функций берём из
него, но требования, противоречащие реальности Hysteria 2 и целевого железа, переписаны — см. раздел «Реестр
отступлений» и `docs/adr/`.

## 1. Цели и границы

**Что делаем.** Монолитный Go-демон со встроенным веб-интерфейсом, который управляет **N экземплярами Hysteria 2 в
роли `server`** на роутерах Keenetic и на серверах VPS. Аудитория — опенсорс («чтобы поставили другие»), лицензия
MIT (уже в репозитории).

**Референс приёмки.** Keenetic Ultra **KN-1811**: `aarch64` (MT7622B, Cortex-A53), ~489 МБ RAM, 256 МБ flash,
Entware на USB-разделе (`/opt`, 55 ГБ свободно), init-система Entware (`rc.func` / `rc.unslung`).

**Что не делаем — никогда** (запреты ТЗ 2.4 сохраняются полностью):

- никаких `/mcp`-эндпоинтов, API-ключей для ИИ-инструментов и экспортных карт для ИИ;
- никаких TUN/TProxy, правок системных таблиц маршрутизации, взаимодействия с внешними роутерами, Sing-box или
  NDMS-API Keenetic;
- никаких правок системного файрвола (следствие — см. ADR-0005).

## 2. Ключевые архитектурные решения

| Область | Решение | Заметки |
|---|---|---|
| Ядро Hysteria | **in-process**, импорт `github.com/apernet/hysteria/core/v2` | ADR-0001 |
| Хранилище | **bbolt** (pure Go), версия схемы + миграции + автобэкап | ADR-0002 |
| Платформы | **`aarch64` + `x86_64`** (остальные `GOARCH` собираются в CI, но не тестируются) | ADR-0003 |
| Фронтенд | Svelte + Vite + Tailwind, SPA, встраивание через `go:embed`, i18n-каркас (RU заполняется, EN позже) | — |
| Транспорт UI | **HTTPS-only на `:2222`**, собственный сертификат | — |
| Аутентификация UI | cookie-сессии, Argon2id, TTL 15 мин, задержка после 5 неудач, без привязки к IP; **пароль по умолчанию выключен** | ADR-0004 |
| Клиенты экземпляра | **multi-user**, свой `Authenticator`; пароли клиентов хранятся **обратимо** | ADR-0006 |
| Квоты | лимит объёма + лимит скорости; блокировка конкретного пользователя | — |
| Метрики | собственный сбор через хук `TrafficLogger` + агрегация; в UI — **SSE** | — |
| Конфигурация | структурированный конфиг в bbolt как источник истины; YAML — экспорт/импорт + «сырой оверрайд» | — |
| Применение конфига | только по кнопке **«Применить»** (перезапуск экземпляра, обрыв сессий) | — |
| TLS | self-signed + принудительный `sniGuard: disable`; ACME DNS-01 (lego) — этап 4 | — |
| Realms (P2P) | поля в схеме зарезервированы, реализация — **этап 3** | — |
| Геобазы ACL | обновляются **явным действием** в UI, без молчаливого скачивания | ADR-0007 |
| Порт-хоппинг | только клиентская часть (URI с диапазоном и интервалом) | ADR-0005 |
| Дистрибуция | GitHub Releases + `install.sh`; `.ipk` и opkg-репозиторий — этап 4; **без самообновления** | ADR-0008 |
| Watchdog | `recover()` + перезапуск экземпляра с экспоненциальным backoff и лимитом попыток | — |
| Логи | кольцевой буфер в памяти (страница логов в UI) + файл с жёсткой ротацией | — |
| Тестирование | loopback-e2e (сервер + клиент в одном процессе) обязателен с первого дня | — |

## 3. Структура репозитория и границы модулей

```
cmd/hysteria2-manager/   точка входа, парсинг флагов, подъём подсистем
internal/instances/      жизненный цикл N экземпляров, применение конфига, watchdog
internal/hycore/         обёртка над ядром Hysteria 2 (in-process), хуки Authenticator/TrafficLogger
internal/store/          bbolt: схема, миграции, доступ к данным
internal/authn/          Argon2id, сессии, CSRF, задержка при переборе
internal/certs/          self-signed, ACME (этап 4), pinSHA256, sniGuard
internal/metrics/        агрегация и история (1ч/5с, 3ч/15с, 24ч/1м, 7д/5м)
internal/api/            REST + SSE
internal/ui/             встроенная SPA (go:embed)
web/                     исходники Svelte + Vite + Tailwind
packaging/               init-скрипт, .ipk, install.sh
```

Границы: **`hycore` — единственный модуль, знающий про Hysteria 2**; `api` и `ui` о нём не знают; `metrics` —
единственное место, знающее про агрегацию; `store` — единственное место, знающее про bbolt.

Важно: `core/v2` принимает готовые `net.PacketConn` и `Authenticator`. Всё, что в оригинале живёт в слое `app/`
(обёртка `obfs`, приём диапазона портов, загрузчик геобаз), лежит под `app/internal/...` и **не импортируется** —
эту обвязку пишем сами в `hycore`.

## 4. Модель данных (bbolt)

| Бакет | Содержимое |
|---|---|
| `meta` | версия схемы, дата создания, версия приложения |
| `instances` | именованные экземпляры: структурированный конфиг, адрес/порт, ссылки на сертификаты |
| `users` | пользователи по экземплярам: логин, пароль (обратимо), квоты, счётчики |
| `sessions` | сессии UI (TTL, CSRF-токены) |
| `appstate` | настройки демона: адрес бинда, хеш пароля UI, язык |
| `metrics` | агрегаты по окнам хранения |
| `events` | журнал событий: watchdog, применение конфига, срабатывание квот |

На диске (не в базе): сертификаты и ключи в `/opt/etc/hysteria2-manager/certs/` (0600), лог-файл с ротацией,
скачанные геобазы. Каталог данных — `/opt/etc/hysteria2-manager/data/`.

## 5. Реестр отступлений от ТЗ

| Пункт ТЗ | Принятое решение | Причина |
|---|---|---|
| 2.3 «SQLite в режиме WAL» | bbolt | SQLite на целевых арх. требует cgo или не поддерживает их; `mattn/go-sqlite3` ломает статическую сборку, `modernc.org/sqlite` не поддерживает MIPS |
| 2.1 «WebSocket в ядре» | SSE на участке демон↔UI, метрики — опросом | у ядра Hysteria нет push-канала: статистика отдаётся только по запросу |
| 2.1 «≤15–20 МБ ОЗУ в простое» | реально замеренный бюджет после MVP | публичного эталона такого норматива нет; `-ldflags "-s -w"` уменьшает размер файла, а не RSS |
| 3.3 «минимум 3 STUN-сервера» | ≥2 рефлексивных порта в группе (gap ≤ 4); 3 STUN — рекомендация по умолчанию | в коде `symmetricNATPortGap = 4`, жёсткого порога «3» нет |
| 1.2 целевые MIPS/MIPSEL | вне области поддержки | Entware на MIPS-моделях Keenetic официально не заявлен; MIPS нет в парке как цель |
| 4.3 «форма входа по мастер-паролю» | пароль по умолчанию выключен, включается вручную | решение владельца с принятым риском (ADR-0004) |
| 3.1 `portHopping` (поле UI) | только клиентская часть | серверный диапазон требует правки nftables/iptables, что запрещено разделом 2.4 |
| 3.1/3.2 ACME в первом релизе | этап 4 | требует внешнего DNS-провайдера и интернета — хуже всего проверяется |
| 3.3 Realms в первом релизе | этап 3 | зависит от внешней инфраструктуры (рандеву, STUN) и условий провайдера |
| 3.4 «остановка туннеля» при квоте | блокировка конкретного пользователя | при multi-user модель «упал один — упали все» неприемлема |
| 4.1 SvelteKit | Svelte + Vite + Tailwind (SPA) | серверный слой SvelteKit избыточен для встроенной SPA; SSR не нужен |
| 4.1 «HTTP :2222» | HTTPS :2222 | cookie-сессия без TLS перехватывается в открытой сети |
| 5.1 «LSB-контракт» init-скрипта | контракт Entware (`rc.func` / `rc.unslung`, `/opt/etc/init.d/S99…`) | Entware не использует `rc.common` OpenWrt и формально не LSB |
| 5.2 `repo.your-domain.zone` + `curl \| sh` | GitHub Releases + `install.sh` | реальный хостинг вместо вымышленного домена |

## 6. Критерии приёмки v0.1

«Готово» = все пункты выполнены на **KN-1811 (`aarch64`)**:

1. `install.sh` ставит бинарь в `/opt/etc/hysteria2-manager/`, создаёт `data/` и `certs/` с правами, ставит
   `S99hysteria2-manager`; `start/stop/restart/status/check` работают; **после перезагрузки роутера демон поднимается сам**.
2. UI поднимается по **HTTPS на `:2222`** с самоподписанным сертификатом; вход работает.
3. Создание экземпляра через UI: порт, multi-user доступ, `obfs: salamander` (опционально), self-signed TLS с
   автоматическим `sniGuard: disable`, лимиты скорости.
4. **Реальный клиент подключается** по сгенерированному `hysteria2://` / QR и гоняет трафик (проверка минимум двумя
   клиентами: официальный CLI + один мобильный).
5. Метрики Rx/Tx в UI обновляются ≤2 с; графики 1ч/3ч/24ч/7д строятся из истории; **история переживает перезапуск демона**.
6. Два клиента онлайн одновременно: статистика и `online`-статус раздельны.
7. Квота: при превышении лимита объёма пользователь отключается и **не может подключиться до сброса**.
8. Смена конфига — только по **«Применить»**, с предупреждением об обрыве; применяется, клиент переподключается.
9. Watchdog: падение ядра → автоподъём с backoff, событие видно в UI.
10. **loopback-e2e зелёный в CI** (авторизация + квота + учёт трафика).
11. Релиз собирает `aarch64` и `x86_64`; CI собирает остальные `GOARCH` без тестов.
12. Миграция схемы bbolt работает и делает бэкап базы перед миграцией.
13. Smoke-прогон на `x86_64` (VPS или локально).

## 7. Этапы

*Длительности не оценены — при необходимости оценим отдельно.*

- **Этап 0 — скелет.** Структура из раздела 3, CI с матрицей сборки, схема bbolt + версия + миграции, HTTPS-сервер
  UI + сессии, встроенная SPA с i18n-каркасом, каркас loopback-e2e.
- **Этап 1 — сквозной один экземпляр.** `hycore` (in-process ядро, свой `Authenticator`, `TrafficLogger` + квоты,
  `obfs`), `instances` (старт/стоп/применение, watchdog), метрики с агрегацией и SSE, экспорт `hysteria2://` + QR.
  Выход: пункты 3–10 приёмки.
- **Этап 2 — пригодность к раздаче.** `install.sh`, init-скрипт, релизные артефакты, ACL (правила по адресам и
  доменам) и геобазы явным действием, прогон на живом Keenetic. Выход: **приёмка v0.1 целиком**.
- **Этап 3 — Realms P2P.** `realm://` / `realm+http://`, STUN, диагностика типа NAT и статуса punch.
- **Этап 4 — расширение.** `.ipk` + opkg-репозиторий, ACME DNS-01, клиентская роль, EN-перевод, экспорт/импорт базы,
  трассировка потоков, уведомления о квоте (80 %/95 %).

## 8. Открытые вопросы

Явно отложены, не решены молча:

- экспорт/импорт всей конфигурации между устройствами (этап 4);
- клиентская роль Hysteria (`client`) — этап 4;
- общий API-токен для автоматизации (не для ИИ-агентов) — нужен ли вообще;
- несколько администраторов UI — сейчас подразумевается один;
- возврат к MIPS, если появится реальная цель (см. ADR-0003: цена возврата известна);
- поведение при `auth.type: password` в комбинации с multi-user моделью — уточнить при разработке.

## 9. Премиса, которую нельзя забывать

На роутере уже стоят сторонние пакеты `S99awg-manager`, `S99hrneo`, `S99hrweb` (поддержка протокола AmneziaWG 3.1).
Они **не решают задачу Hysteria 2** и будут удалены владельцем после ввода `hysteria2-manager` в строй. Проверять
конфликты портов и имён init-скриптов при установке.
