# План реализации Hysteria Ward

Итог проектировочной сессии, пересмотренный после смены области проекта. Техническое задание считается
**черновиком**: объём функций берём из него, но требования, противоречащие реальности Hysteria 2 и целевым
платформам, переписаны — см. раздел «Реестр отступлений» и `docs/adr/`.

## 1. Цели и границы

**Что делаем.** Панель управления сервером Hysteria 2 на VPS. Монолитный Go-демон со встроенным веб-интерфейсом:
ставится одним скриптом на чистый сервер, сам выпускает сертификат для домена, ведёт список пользователей, выдаёт
ссылки `hysteria2://` и показывает статистику.

**Референс приёмки.** Чистый VPS с `x86_64` и сетевой доступностью: Ubuntu LTS и Debian 12/13. Вторичная
платформа — `aarch64` (ARM-VPS), собирается и проверяется, но не является основной.

**Что не делаем:**

- никаких TUN/TProxy, правок системных таблиц маршрутизации и системного файрвола. Панель серверная, ей это не
  нужно: она не маршрутизирует чужой трафик, а обслуживает входящие подключения клиентов;
- клиентская роль Hysteria 2 — панель управляет только сервером;
- роутерная часть (Keenetic) — **отдельный репозиторий**, форк `awg-manager` (ADR-0009). Здесь её нет.

## 2. Ключевые архитектурные решения

| Область | Решение | Заметки |
|---|---|---|
| Ядро Hysteria | **in-process**, импорт `github.com/apernet/hysteria/core/v2` | ADR-0001 |
| Хранилище | **bbolt** (pure Go), версия схемы + миграции + автобэкап | ADR-0002 |
| Платформы | **`x86_64`** основная, **`aarch64`** вторичная | ADR-0003 |
| Фронтенд | Svelte + Vite + Tailwind v4, SPA, `go:embed`; **SvelteKit не используем**; i18n — **Paraglide**, ru и en | SSR и серверный слой не нужны |
| Транспорт UI | **HTTPS на домене `panel.<домен>`**, сертификат ACME | ADR-0010 |
| Аутентификация | **обязательна**; Argon2id, cookie-сессии, CSRF, задержка при переборе | ADR-0010 |
| Режим доступа | по умолчанию панель слушает `127.0.0.1` и доступна только через SSH-туннель; публичный доступ включается явно, на ходу и без перезапуска | ADR-0013 |
| Пользователи | multi-user, пароли хранятся **обратимо**, выпуск `hysteria2://` + QR, ключ собирается по текущим настройкам | ADR-0006, ADR-0014 |
| Сервер | **один** сервер Hysteria 2 на VPS; модель данных допускает N | открытый вопрос 1 |
| Метрики | сбор через `TrafficLogger`; приросты снимаются раз в секунду, окна 1ч/5с, 3ч/15с, 24ч/1м, 7д/5м; в UI — **SSE** | ADR-0015 |
| Конфигурация | структурированный конфиг в bbolt как источник истины; YAML — экспорт/импорт | — |
| Применение конфига | только по кнопке **«Применить»** (перезапуск сервера, обрыв сессий) | — |
| Сертификаты | ACME **HTTP-01** по умолчанию, DNS-01 через Cloudflare или хук; self-signed только для отладки | — |
| Masquerade | выбор при установке: `file` (свой сайт), `proxy` (зеркало чужого) или выключено | ADR-0016 |
| Обновление | `update.sh`: версионирование, идемпотентные миграции, `--dry-run`/`--status`/`--repair` | ADR-0011 |
| MCP | **разрешён**, отдельным этапом | ADR-0012 |
| Дистрибуция | GitHub Releases + `install.sh` | ADR-0008 |
| Автозапуск | systemd (`hysteria-ward.service`) | — |
| Логи | кольцевой буфер в памяти (страница логов в UI) + файл с ротацией | — |
| Тестирование | loopback-e2e (сервер + клиент в одном процессе) обязателен с первого дня | — |

## 3. Структура репозитория и границы модулей

```
cmd/hysteria-ward/       точка входа: сигналы, потоки процесса, код возврата
internal/build/          метаданные сборки: версия, коммит, платформа
internal/cli/            разбор аргументов, диспетчер команд, сборка подсистем
internal/hycore/         обёртка над ядром Hysteria 2 (in-process), хуки Authenticator/TrafficLogger
internal/config/         конфигурация сервера структурой + экспорт/импорт YAML
internal/store/          bbolt: схема, миграции, доступ к данным
internal/logging/        журнал: кольцевой буфер в памяти + файл с ротацией
internal/daemon/         жизненный цикл: база, журнал, ядро, применение конфигурации, остановка
internal/authn/          Argon2id, сессии, CSRF, задержка при переборе
internal/users/          пользователи в памяти: авторизация ядра, учёт трафика, кто подключён
internal/keys/           сборка ключа `hysteria2://` и отпечаток сертификата
internal/certs/          ACME, self-signed, pinSHA256
internal/metrics/        агрегация и история (1ч/5с, 3ч/15с, 24ч/1м, 7д/5м)
internal/api/            HTTPS-сервер панели: REST + SSE (интерфейс отдаётся обработчиком из ui)
internal/e2e/            каркас loopback-e2e: панель целиком по HTTPS, сценарии отдельно
internal/ui/             встроенная SPA (go:embed), собранная из web/
web/                     исходники Svelte + Vite + Tailwind + Paraglide
packaging/               install.sh, update.sh, systemd-юнит
```

Границы: **`hycore` — единственный модуль, знающий про Hysteria 2**; `api` и `ui` о нём не знают; `users` —
единственный модуль, знающий, кого пускать и кому можно трафик; `keys` — единственный, знающий, из чего
складывается ссылка клиента; `metrics` —
единственное место, знающее про агрегацию; `store` — единственное место, знающее про bbolt; `config` —
единственное место, знающее, из чего состоит конфигурация сервера; `daemon` — единственное место, знающее
жизненный цикл ядра и порядок его перезапуска.

Команд три: `serve` поднимает панель, `passwd` задаёт пароль администратора, `setup` записывает ответы
конфигуратора установки. `passwd` и `setup` — то, что приходится говорить панели мимо интерфейса; обе вызывает
`install.sh`. Пароль приходит из трубы одной строкой, а с терминала спрашивается скрыто и дважды; базу команды
открывают сами, поэтому перед ними панель останавливают — пока она работает, база занята. `setup` пишет домен,
e-mail ACME, конфигурацию сервера, доступ к панели и пароль одной транзакцией и отказывается переписывать уже
настроенную базу (ADR-0017).

**loopback-e2e.** `internal/e2e` поднимает панель целиком — база, сертификат, настройки, `serve` — на свободном
порту и ждёт готовности по `GET /api/health`. Сценарий получает готовую панель и работает по настоящему HTTPS:
проверка работоспособности, вход, защищённый эндпоинт, выход. Запуск, ожидание и остановка живут в каркасе, а
сценарий — обычная функция; новый сценарий не требует правок в каркасе. Остановка проверяется: панель
завершается с кодом 0 и отпускает порт, временный каталог принадлежит тесту. В CI прогон вынесен отдельным
шагом `make e2e`, чтобы поломка авторизации была видна сразу.

Сборка интерфейса — `make ui`: она кладёт результат в `internal/ui/dist`, а оттуда его забирает `go:embed`.
Собранный интерфейс **лежит в репозитории**, поэтому `go build` и `go test` работают в любом клоне без Node.js,
а на сервере не появляется ни интерпретаторов, ни файлов рядом с бинарём. Плата за это — собранное может
отстать от `web/`; в CI это ловится отдельной задачей.

Из сети сборке нужен только `npm ci`: плагины i18n подключаются из `node_modules`, а не с чужого CDN, поэтому их
целостность проверяет npm.

Важно: `core/v2` принимает готовые `net.PacketConn` и `Authenticator`. Обвязка, которая в оригинале живёт в слое
`app/`, вынесена в отдельный **импортируемый** модуль `github.com/apernet/hysteria/extras/v2`: обфускация
(`obfs` — salamander и gecko), приём диапазона портов (`transport/udphop`), masquerade (`masq`), заготовки
аутентификации (`auth`). Своё пишем только там, где в `extras` ничего нет.

## 4. Модель данных (bbolt)

| Бакет | Содержимое |
|---|---|
| `meta` | версия схемы, дата создания, версия приложения |
| `config` | структурированный конфиг сервера: адрес и порт, TLS, obfs, masquerade |
| `auth` | учётные данные администратора: имя и Argon2id-хеш пароля |
| `users` | пользователи: идентификатор, имя, пароль (обратимо), признак включённости, месячная квота, даты |
| `sessions` | сессии интерфейса панели: токен, CSRF-токен, время последнего обращения |
| `appstate` | настройки панели: домен, e-mail и способ проверки ACME, порт, режим доступа, язык |
| `metrics` | окна истории по пользователям и накопленные итоги (вложенные бакеты `series` и `totals`) |
| `quota` | расход пользователей за текущий месяц и начало периода (ADR-0019) |
| `apikeys` | ключи MCP: идентификатор, имя, SHA-256-хеш токена и дата выпуска (ADR-0012) |
| `events` | журнал событий: применение конфига, watchdog, входы в панель |

На диске (не в базе): сертификаты и ключи в `/etc/hysteria-ward/certs/` (0600; сертификат — `fullchain.pem`,
ключ — `privkey.pem`, ключ учётной записи ACME — `acme-account.key`), каталог данных `/var/lib/hysteria-ward/`,
лог-файл с ротацией — `/var/log/hysteria-ward/`.

Пути — по FHS, а не как было в Entware-варианте: на VPS это стандартный Linux, и раскладывать данные по `/opt/etc`
незачем.

## 5. Реестр отступлений от ТЗ

| Пункт ТЗ | Принятое решение | Причина |
|---|---|---|
| 1.1 «Идентификатор системы `hysteria2-manager`» | **`hysteria-ward`** | идентификатор дословно означал «менеджер Hysteria 2», то есть намекал на роутерный продукт, вынесенный отсюда (ADR-0009); двух имён на один продукт быть не должно |
| Целевые платформы Keenetic и OpenWrt | только Linux VPS | роутерная часть вынесена в отдельный репозиторий (ADR-0009) |
| 2.3 «SQLite в режиме WAL» | bbolt | SQLite требует cgo либо не поддерживает целевые арх.; `mattn/go-sqlite3` ломает статическую сборку (ADR-0002) |
| 2.1 «WebSocket в ядре» | SSE на участке демон↔UI, метрики — опросом | у ядра Hysteria нет push-канала: статистика отдаётся только по запросу |
| 2.4 «никаких `/mcp`-эндпоинтов» | MCP разрешён | решение владельца (ADR-0012) |
| 1.2 целевые MIPS/MIPSEL | вне области поддержки | MIPS нет в парке как цель (ADR-0003) |
| 4.3 «форма входа по мастер-паролю» | авторизация обязательна всегда | панель стоит на публичном адресе; пароль по умолчанию выключен был решением под домашний роутер (ADR-0010) |
| 3.1/3.2 ACME в первом релизе | ACME в MVP, HTTP-01 по умолчанию | без сертификата панель на домене не поднять |
| 3.1 `portHopping` (поле UI) | только клиентская часть | серверный диапазон требует правки nftables/iptables (ADR-0005) |
| 3.4 «остановка туннеля» при квоте | блокировка конкретного пользователя | при multi-user модель «упал один — упали все» неприемлема |
| 4.1 SvelteKit | Svelte + Vite + Tailwind v4 (SPA) | серверный слой и SSR встроенной SPA не нужны; маршрутизацию пишем сами. Отступление принято осознанно, хотя роутерный менеджер использует SvelteKit с `adapter-static` |
| 4.1 «HTTP :2222» | HTTPS на домене | cookie-сессия без TLS перехватывается в открытой сети |
| 5.1 «LSB-контракт» init-скрипта | systemd-юнит | целевая ОС — Ubuntu и Debian, а не Entware |
| 5.2 `repo.your-domain.zone` + `curl \| sh` | GitHub Releases + `install.sh` | реальный хостинг вместо вымышленного домена (ADR-0008) |
| «N экземпляров» | один сервер | новый объём задачи описывает один сервер на VPS |
| ACL и геобазы | вне MVP | в новом объёме задачи не упомянуты |
| Квоты и лимиты скорости | вне MVP; месячные квоты и глобальные пределы — этап 4 | в MVP входил только просмотр статистики; персональные пределы ядро не умеет (ADR-0019) |
| Realms (P2P) | вне области | механизм нужен там, где нет публичного адреса; у VPS он есть |

## 6. Критерии приёмки v0.1

«Готово» = все пункты выполнены на чистом VPS (Ubuntu LTS и Debian 12/13):

1. `install.sh` на чистом сервере собирает ответы конфигуратора и проходит без ручных шагов; повторный запуск
   безопасен и не переписывает настройки.
2. Панель открывается по **HTTPS на `panel.<домен>:8443`** (в публичном режиме) с валидным сертификатом, без
   предупреждений браузера.
3. **Авторизация обязательна**: без входа панель не отдаёт ничего, кроме страницы входа.
4. По умолчанию панель слушает `127.0.0.1`; публичный доступ включается и выключается одной операцией, без
   перезапуска панели, а с паролем по умолчанию не включается вовсе.
5. Создание и удаление пользователя; выпуск ссылки `hysteria2://` и QR.
6. **Реальный клиент подключается** по выпущенной ссылке и гоняет трафик.
7. Статистика по пользователям обновляется ≤2 с; графики 1ч/3ч/24ч/7д строятся из истории; **история переживает
   перезапуск панели**.
8. Masquerade: при включённом режиме посторонний запрос получает подставной ответ, при выключенном — нет.
9. `update.sh` обновляет панель, **не теряя пользователей, пароли, домен и сертификаты**; повторный запуск
   безопасен, `--dry-run` ничего не меняет.
10. **loopback-e2e зелёный в CI** (авторизация + выпуск ключа + учёт трафика).
11. Миграция схемы bbolt работает и делает бэкап базы перед миграцией.

## 7. Этапы

*Длительности не оценены — при необходимости оценим отдельно.*

- **Этап 0 — фундамент.** Структура из раздела 3, CI с матрицей сборки, схема bbolt + версия + миграции,
  конфиг и «Применить», ядро Hysteria 2 in-process, жизненный цикл сервера и логи.
- **Этап 1 — панель.** HTTPS-сервер на домене + встроенная SPA с i18n, авторизация, режим SSH-туннеля,
  пользователи и выпуск ключей, метрики с агрегацией и SSE, masquerade.
- **Этап 2 — установка и эксплуатация.** `install.sh`, интерактивный конфигуратор, домен и ACME, `update.sh`.
- **Этап 3 — приёмка.** loopback-e2e, прогон на чистом VPS обеих ОС, приёмка v0.1 целиком.
- **Этап 4 — расширение.** MCP-сервер для ИИ-агентов (read-only готов: `server_status`, `users_list`,
  `traffic_snapshot`; изменяющие инструменты — отдельное решение), EN-перевод и встроенный DNS-провайдер
  Cloudflare для ACME DNS-01 готовы. Остаются остальные DNS-провайдеры, ACL и геобазы, экспорт/импорт
  конфигурации между устройствами. Месячные квоты трафика и глобальные пределы скорости сделаны (ADR-0019);
  персональные пределы скорости ядро Hysteria 2 не поддерживает — это отдельная задача, если понадобятся.

### Установка

`install.sh` работает на Ubuntu LTS и Debian 12/13: ставит зависимости из штатного репозитория (без компиляции
на месте), заводит непривилегированного пользователя `hysteria-ward` (единственная привилегия — право занять
443/80), создаёт каталоги по FHS, раскладывает бинарь и systemd-юнит из GitHub Releases и запускает службу.

Установка спрашивает домен, e-mail для ACME, режим доступа к панели и режим masquerade. Вопросы задаются, только
если stdin — терминал; без терминала нужны явные флаги, и скрипт сразу перечисляет недостающие, а не ждёт ввода.
Ответы проверяются до установки пакетов и пользователя, показываются на подтверждение и записываются командой
`hysteria-ward setup` одной транзакцией до запуска службы (ADR-0017). Пароль администратора не спрашивается: он
генерируется при установке и печатается один раз последним блоком вывода. Флага с самим паролем нет; свой пароль
можно передать только файлом.

На первой установке скрипт обновляет систему (`apt update` и `apt upgrade -y`; `--skip-upgrade` пропускает шаг)
и сам ставит `curl`, `tar` и `gzip`, если их нет в минимальном образе. Проверка `curl` отдельная: без него не
скачать релиз, и сообщение должно говорить об этом, а не о неудачном скачивании.

Повторный запуск идемпотентен: база, пользователи, пароль и сертификаты не пересоздаются. Ответы конфигуратора
применяются только к пустой базе; на настроенной панели обновляются бинарь, юнит и режим сертификата.

Пока настоящего сертификата нет, панель получает самоподписанный через drop-in юнита: без него на чистом сервере
её запускать нечем, ведь сертификат появляется только на шаге ACME. `setup` сразу указывает пути к будущим
файлам ACME (`fullchain.pem` и `privkey.pem`), а появление сертификата в `/etc/hysteria-ward/certs/` выключает
drop-in при следующем запуске установщика.

Сертификат выпускает сама панель (ADR-0018). Один сертификат покрывает `<домен>` и `panel.<домен>`: по первому
подключаются клиенты Hysteria, по второму открывается панель. По умолчанию используется HTTP-01 — на время
выпуска панель занимает порт 80. DNS-01 включается флагом `--acme-mode dns`: для Cloudflare работает встроенный
провайдер (`--acme-dns-provider cloudflare --acme-dns-token-file ...`), для остальных — внешняя программа
`--acme-dns-hook` (ей передаются `present`/`cleanup`, имя и значение TXT-записи). Настройки ACME лежат в
`appstate` и записываются установщиком вместе с остальными ответами; адрес каталога можно подменить через
`--acme-directory` для испытательного ACME.

На уже настроенной панели способ проверки и DNS-провайдер меняет `hysteria-ward acme` при остановленной службе:
без флагов команда показывает текущие настройки, с флагами — записывает только указанные поля. Переход на
Cloudflare больше не требует ручной правки базы. Смена через UI/API не входит в эту задачу: секрет не должен
попадать в браузер без отдельного решения о его защите.

Продление идёт в фоне и не останавливает панель: HTTPS-слушатель берёт сертификат при каждом рукопожатии.
Новые ключи `hysteria2://` считают `pinSHA256` по текущему сертификату, поэтому отпечаток не расходится с тем,
что предъявляет ядро. Смена домена из интерфейса перевыпускает сертификат сразу: фоновая проверка сравнивает
имена в нём с нужными, а не ждёт продления. Провал выпуска не отнимает вход: панель остаётся на самоподписанном сертификате, причина
видна в `GET /api/certificate`, а повтор запускается `POST /api/certificate/issue` и автоматически с
нарастающей паузой. После успешного выпуска панель сама применяет конфигурацию, чтобы ядро подхватило файл.

### Обновление

`update.sh` обновляет уже установленную панель до последней или указанной версии. Архив и `checksums.txt`
скачиваются из GitHub Releases, sha256 сверяется до изменений. Перед заменой служба останавливается, база
копируется в `/var/lib/hysteria-ward/backups/`, прежний бинарь сохраняется рядом. После запуска скрипт ждёт
устойчивого `active` и совпадения версии; если новая версия не поднялась, возвращает прежний бинарь и копию
базы. Пользователи, пароль, домен и сертификаты не пересоздаются.

`--dry-run` показывает план и ничего не меняет, `--status` показывает версию, состояние службы, настройки из
базы, сертификат и порты, `--repair` останавливает службу, приводит каталоги и права в порядок и дополняет
недостающие настройки умолчаниями командой `hysteria-ward config --repair` (не меняя домен, пароль и
пользователей). Повторный запуск с уже установленной версией пропускает замену; `--force` переустанавливает её.

## 8. Открытые вопросы

Явно отложены, не решены молча:

- **один сервер или N**: MVP исходит из одного, схема это допускает; цена возврата к N — новая сущность в модели,
  переключатель в UI и отдельные счётчики на сервер;
- персональные лимиты скорости: ядро Hysteria 2 умеет только глобальные; нужен ли шейпер поверх сокета —
  отдельный вопрос и отдельный ADR;
- формат страницы masquerade по умолчанию: свой сайт или зеркало;
- TCP-часть masquerade (80/443): сейчас посторонний запрос получает ответ только по HTTP/3; порт 80 занят
  только на время HTTP-01, TCP-слушатели masquerade появятся отдельным шагом и должны уживаться с проверкой;
- что показывать на `panel.<домен>` при доступе по IP напрямую;
- несколько администраторов панели — сейчас подразумевается один;
- API-токен для автоматизации (не для ИИ-агентов) — нужен ли вообще; MCP-ключ для этого не годится, потому
  что даёт только чтение.

## 9. Связь с роутерной частью

Управление Hysteria 2 на роутерах Keenetic ведётся в **отдельном репозитории** — форке `hoaxisr/awg-manager`
(MIT). Оттуда не берётся ни строки кода в этот проект, и наоборот: у продуктов разные аудитории, разные целевые
платформы и разные релизные циклы. Общими остаются только протокол и формат ссылок `hysteria2://`.
