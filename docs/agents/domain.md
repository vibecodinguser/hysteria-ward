# Доменные доки

Как инженерные скиллы должны потреблять доменную документацию этого репозитория, исследуя кодовую базу.

## Перед исследованием прочитай

- **`GLOSSARY.md`** в корне репозитория, либо
- **`GLOSSARY-MAP.md`** в корне, если он есть: он указывает на по одному `GLOSSARY.md` на контекст. Прочитай каждый, относящийся к теме.
- **`docs/adr/`**: прочитай ADR, затрагивающие область, в которой собираешься работать. В мультиконтекстных репозиториях проверь также `src/<context>/docs/adr/` на предмет решений уровня контекста.

Если каких-то из этих файлов нет — **проходи молча**. Не поднимай вопрос об их отсутствии и не предлагай заранее их создать. Скилл `/domain-modeling` (доступный через `/grill-with-docs` и `/improve-codebase-architecture`) создаёт их лениво, когда термины или решения действительно разрешаются.

## Структура файлов

Одноконтекстный репозиторий (большинство репозиториев):

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

Мультиконтекстный репозиторий (признак — `GLOSSARY-MAP.md` в корне):

```
/
├── GLOSSARY-MAP.md
├── docs/adr/                          ← общесистемные решения
└── src/
    ├── ordering/
    │   ├── GLOSSARY.md
    │   └── docs/adr/                  ← решения уровня контекста
    └── billing/
        ├── GLOSSARY.md
        └── docs/adr/
```

Этот репозиторий — **одноконтекстный**.

## Используй словарь глоссария

Когда твой результат называет доменное понятие (в заголовке задачи, в предложении по рефакторингу, в гипотезе, в имени теста), используй термин в том виде, как он определён в `GLOSSARY.md`. Не сползай к синонимам, которые глоссарий явно запрещает.

Если нужного понятия в глоссарии ещё нет — это сигнал: либо ты изобретаешь язык, которого в проекте нет (передумай), либо это реальный пробел (отметь его для `/domain-modeling`).

## Подсвечивай конфликты с ADR

Если твой результат противоречит существующему ADR, скажи об этом явно, а не переопределяй молча:

> _Противоречит ADR-0007 (event-sourced orders), но стоит переоткрыть, потому что…_
