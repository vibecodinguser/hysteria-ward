# Hysteria Ward

Панель управления сервером [Hysteria 2](https://v2.hysteria.network/) на VPS. Ставится одним скриптом на чистый
сервер, сама выпускает сертификат для домена, ведёт пользователей, выдаёт ключи `hysteria2://` и показывает
статистику.

## Статус

Реализация идёт по этапам [`docs/plan.md`](docs/plan.md): панель, встроенное ядро Hysteria 2, пользователи и
ключи, метрики, masquerade и установщик с интерактивным конфигуратором уже работают. Установка на чистый сервер —
`packaging/install.sh` из релиза.

## Установка

Нужен чистый сервер Ubuntu LTS (20.04, 22.04, 24.04, 26.04) или Debian 12/13 на `x86_64` либо `aarch64`.

```sh
curl -fsSL https://github.com/vibecodinguser/hysteria-ward/releases/latest/download/install.sh -o install.sh
sudo sh install.sh
```

Установщик спросит домен, e-mail для ACME, режим доступа к панели, режим masquerade и пароль администратора.
Пароль вводится скрыто; если оставить его пустым, установщик сгенерирует пароль и покажет его один раз. Ответы
проверяются до изменений в системе и показываются на подтверждение.

Без терминала вопросы не задаются — нужны явные флаги:

```sh
sudo sh install.sh \
  --domain example.com \
  --email admin@example.com \
  --access tunnel \
  --masquerade off \
  --generate-password
```

`--version v0.1.0` ставит конкретную версию, `--help` показывает справку. Повторный запуск обновляет бинарь и
systemd-юнит, но не трогает базу, пользователей, пароль и сертификаты: ответы конфигуратора применяются только
к пустой базе.

Сменить пароль позже:

```sh
sudo systemctl stop hysteria-ward
sudo runuser -u hysteria-ward -- hysteria-ward passwd
sudo systemctl start hysteria-ward
```

Панель по умолчанию слушает только `127.0.0.1`: попасть в неё можно через SSH-туннель, а публичный доступ
включается уже из интерфейса.

```sh
ssh -L 8443:127.0.0.1:8443 root@<адрес-сервера>
# затем https://127.0.0.1:8443
```

Пока для домена нет сертификата ACME, панель поднимается с самоподписанным — браузер предупредит о
недоверенном сертификате.

## Что планируется

- Веб-панель по HTTPS на `panel.<домен>`, с обязательной авторизацией.
- По умолчанию панель доступна только через SSH-туннель; публичный доступ включается и выключается осознанно.
- Пользователи: создание, удаление, выпуск ключа `hysteria2://` и QR-кода.
- Статистика по каждому пользователю с историей за 1 ч / 3 ч / 24 ч / 7 суток, переживающая перезапуск панели.
- Masquerade: подставной ответ посторонним запросам — свой сайт или зеркало чужого.
- Обновление панели скриптом `update.sh`, не теряющее данные; повторный запуск безопасен.

Ядро Hysteria 2 работает **внутри процесса панели**, а не отдельной службой: это даёт прямой доступ к авторизации
клиентов и учёту трафика по каждому из них.

## Чего проект не делает

- Не управляет маршрутизацией, не создаёт сетевые интерфейсы, не правит файрвол. Панель обслуживает входящие
  подключения и в маршрутизацию чужого трафика не вмешивается.
- Не является клиентом Hysteria 2 — только сервером.
- Не управляет Hysteria 2 на роутерах. Для Keenetic — отдельный проект на базе
  [`awg-manager`](https://github.com/hoaxisr/awg-manager).
