# Hysteria Ward

Панель управления сервером [Hysteria 2](https://v2.hysteria.network/) на VPS. Ставится одним скриптом на чистый
сервер, сама выпускает сертификат для домена, ведёт пользователей, выдаёт ключи `hysteria2://` и показывает
статистику.

## Статус

Реализация идёт по этапам [`docs/plan.md`](docs/plan.md): панель, встроенное ядро Hysteria 2, пользователи и
ключи, метрики, masquerade, установщик с интерактивным конфигуратором, автоматический выпуск сертификата,
MCP-сервер только для чтения и русский/английский интерфейс уже работают. Текущий релиз —
[`v0.4.0`](https://github.com/vibecodinguser/hysteria-ward/releases/tag/v0.4.0). Установка на чистый сервер —
`packaging/install.sh` из релиза.

## Установка

Нужен чистый сервер Ubuntu LTS (20.04, 22.04, 24.04, 26.04) или Debian 12/13 на `x86_64` либо `aarch64`.

Если на свежем сервере ещё нет `curl`, поставьте его штатным пакетным менеджером — иначе скачать установщик
нечем:

```sh
sudo apt-get update
sudo apt-get install -y curl ca-certificates
```

Дальше:

```sh
curl -fsSL https://github.com/vibecodinguser/hysteria-ward/releases/latest/download/install.sh -o install.sh
sudo sh install.sh
```

На первой установке скрипт сам выполняет `apt update` и `apt upgrade -y` и при необходимости ставит `curl`, `tar`
и `gzip`. `--skip-upgrade` пропускает обновление системы, если оно уже сделано.

Установщик спросит домен, e-mail для ACME, режим доступа к панели и режим masquerade. Пароль администратора не
спрашивается: он генерируется при установке и показывается один раз в самом конце. Ответы проверяются до
изменений в системе и показываются на подтверждение.

Без терминала вопросы не задаются — нужны явные флаги:

```sh
sudo sh install.sh \
  --domain example.com \
  --email admin@example.com \
  --access tunnel \
  --masquerade off
```

`--version v0.4.0` ставит конкретную версию, `--help` показывает справку. Повторный запуск обновляет бинарь и
systemd-юнит, но не трогает базу, пользователей, пароль и сертификаты: ответы конфигуратора применяются только
к пустой базе. Свой пароль вместо сгенерированного задаётся `--password-file`.

Сертификат панель выпускает сама: один сертификат на `example.com` и `panel.example.com`. По умолчанию это
HTTP-01 — на время выпуска панель занимает порт 80, поэтому домен должен уже указывать на сервер, а порт 80
быть свободен. Если порт 80 закрыт или домен обслуживает чужой DNS, включите DNS-01 и передайте программу,
которая заводит TXT-записи:

```sh
sudo sh install.sh \
  --domain example.com \
  --email admin@example.com \
  --acme-mode dns \
  --acme-dns-hook /usr/local/bin/my-dns-hook \
  --access tunnel \
  --masquerade off
```

Хук вызывается как `хук present <имя> <значение>` и `хук cleanup <имя> <значение>`. Адрес ACME-каталога можно
подменить через `--acme-directory` — например, для испытательного сервера ACME.

Сменить пароль позже:

```sh
sudo systemctl stop hysteria-ward
sudo runuser -u hysteria-ward -- hysteria-ward passwd
sudo systemctl start hysteria-ward
```

Панель по умолчанию слушает только `127.0.0.1`: попасть в неё можно через SSH-туннель, а публичный доступ
включается уже из интерфейса.

```sh
ssh -L 8443:127.0.0.1:8443 root@<адрес-сервера>
# затем https://127.0.0.1:8443
```

Пока настоящего сертификата нет, панель поднимается с самоподписанным — браузер предупредит о недоверенном
сертификате. Выпуск идёт в фоне и не мешает войти; причина отказа и кнопка повтора доступны в
`GET`/`POST /api/certificate`. После выпуска панель открывается по `https://panel.<домен>:8443` (в публичном
режиме доступа) с сертификатом без предупреждений. Продление тоже идёт в фоне и не останавливает панель.

## Обновление

```sh
curl -fsSL https://github.com/vibecodinguser/hysteria-ward/releases/latest/download/update.sh -o update.sh
sudo sh update.sh                 # последняя версия
sudo sh update.sh --version v0.4.0
sudo sh update.sh --dry-run       # только план
sudo sh update.sh --status        # версия, служба, сертификат, порты
sudo sh update.sh --repair        # привести настройки и права в порядок
```

Перед заменой скрипт снимает копию базы в `/var/lib/hysteria-ward/backups/`, а прежний бинарь держит рядом до
успешного запуска. Если новая версия не поднялась, прежний бинарь и копия базы возвращаются автоматически.
Пользователи, пароли, домен и сертификаты не пересоздаются: обновление меняет только бинарь, systemd-юнит и
(при `--repair`) недостающие поля настроек. Повторный запуск с уже установленной версией ничего не делает.

## MCP

Панель умеет отдавать ИИ-агентам состояние сервера по протоколу MCP. Это отдельная поверхность только для чтения:
ключ не открывает `/api/`, не заменяет вход администратора и не может менять пользователей, сервер или
сертификат.

Ключ выпускается в **Настройки → MCP**. Токен показывается один раз; в базе хранится только его SHA-256-хеш.
Отозванный ключ перестаёт работать сразу. Если панель спрятана за SSH-туннелем, MCP доступен через тот же
туннель; для удалённого агента панель нужно открыть наружу.

```text
POST https://panel.<домен>:8443/mcp
Authorization: Bearer <токен>
Content-Type: application/json
```

Поддерживаются streamable HTTP без SSE и три инструмента: `server_status`, `users_list` и `traffic_snapshot`.
Пароли клиентов и ссылки `hysteria2://` через MCP не отдаются. Подробности решения — в
[ADR-0012](docs/adr/0012-mcp-server-allowed.md).

## Разработка

```sh
make test    # модульные тесты
make e2e     # панель целиком по HTTPS: вход, защищённый эндпоинт, выпуск ключа
make ui      # пересобрать интерфейс в internal/ui/dist
make lint
```

loopback-e2e поднимает панель на свободном порту с настоящим HTTPS и проходит сценарий от проверки
работоспособности до защищённого эндпоинта. Сценарии лежат в `internal/e2e/e2e_test.go`; запуск, ожидание
готовности и остановка — в каркасе, поэтому новый сценарий не требует правок в нём.

## Что уже работает

- Веб-панель по HTTPS на `panel.<домен>`, с обязательной авторизацией.
- По умолчанию панель доступна только через SSH-туннель; публичный доступ включается и выключается осознанно.
- Пользователи: создание, удаление, выпуск ключа `hysteria2://` и QR-кода.
- Месячные квоты трафика: при исчерпании пользователь не авторизуется, а его соединения закрываются; расход
  переживает перезапуск, сброс доступен из интерфейса.
- Глобальные пределы скорости `up`/`down` в Мбит/с с проверкой минимума, который принимает ядро.
- Статистика по каждому пользователю с историей за 1 ч / 3 ч / 24 ч / 7 суток, переживающая перезапуск панели.
- Masquerade: подставной ответ посторонним запросам — свой сайт или зеркало чужого.
- Автоматический выпуск и продление сертификата: HTTP-01 по умолчанию, DNS-01 через внешний хук.
- MCP-сервер только для чтения с отдельными отзываемыми ключами: состояние сервера, пользователи и снимок трафика.
- Русский и английский интерфейс: язык переключается на форме входа и в шапке, выбор запоминается в браузере.

Приёмка v0.1–v0.4 пройдена на публичном сервере: установка, сертификат, клиент, статистика, квоты, `update.sh`
без потери данных, MCP и переключение RU/EN вживую. Порядок проверки и результаты — в
[`docs/acceptance.md`](docs/acceptance.md). Этап 4 из [`docs/plan.md`](docs/plan.md) продолжается: MCP-сервер в
объёме только для чтения и EN-перевод уже работают.

Ядро Hysteria 2 работает **внутри процесса панели**, а не отдельной службой: это даёт прямой доступ к авторизации
клиентов и учёту трафика по каждому из них.

## Чего проект не делает

- Не управляет маршрутизацией, не создаёт сетевые интерфейсы, не правит файрвол. Панель обслуживает входящие
  подключения и в маршрутизацию чужого трафика не вмешивается.
- Не является клиентом Hysteria 2 — только сервером.
- Не ограничивает скорость отдельного пользователя: ядро Hysteria 2 умеет только глобальные пределы. Квота
  трафика при этом персональная.
- Не управляет Hysteria 2 на роутерах. Для Keenetic — отдельный проект на базе
  [`awg-manager`](https://github.com/hoaxisr/awg-manager).
